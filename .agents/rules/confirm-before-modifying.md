# Confirm Before Modifying Rule

1. **No Unconfirmed Modifications**: Never proactively delete, refactor, or edit existing files when the user is asking consultative, architectural, or design questions.
2. **Clarify Intent**: Treat questions starting with "Why", "Is it good practice", "What do you think", or general feedback as discussion topics. Present reasoned options and await explicit instruction before modifying files.
3. **Transparent Change Proposals**: When changes are requested or proposed, outline the exact changes to be made and confirm alignment before executing.
